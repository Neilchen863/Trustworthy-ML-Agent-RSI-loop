# First experiment: ROAP loop + one held-out check (written before round 0 finished)

Budget: $20 total (`rsi budget`). $6 of it is kept for the held-out check, so ROAP rounds stop once
spent + $3 reserve would pass $14.

## Each round t on random_acts_of_pizza (train)

1. `collect` round t (delivery check must pass; a delivery failure stops the loop until fixed).
2. `improve` round t -> H{t+1} (gpt-4o, at most $0.5 per session).
3. Submit round t+1 unless a stop rule below holds.

## Stop rules for the ROAP loop (any one)

- Budget: spent + $3 > $14.
- Two consecutive `no_change` sessions (the improver sees nothing to fix).
- An improver session ends `error`/`unfinished`/`rejected` twice in a row.
- A run fails as infrastructure (no journal, killed job): resubmit once; a second failure stops.

## Held-out check (insults, test role)

After the loop stops: run insults once with H0 and once with H_final (the last harness), same budget.
Report both reward vectors and both official scores (read for the report only; never written to memory).
Skip if H_final == H0.

## How results are read

n = 1 run per harness. No round-to-round change is called an effect. What is reported: the trajectory of
the reward vector, what each harness edit was and which verifier it cited, and whether the verifier the
edit targeted moved in the next round. Execution failures count as outcomes (score 0 / reward -1), not
missing data.

## Change after round 0 (before any improve session)

Round 0 (job 1496637, H0): 9 scored nodes reported in-sample AUC 0.977-0.996 (a stacking meta-model scored
on its own training rows: "Evaluate on train set for sanity check"). No train-only field was involved. The
0.99 `implausible_val` caught only 3 of them, so `selection` called a 0.985 node "trusted".
Thresholds changed to sit well above honest leaderboard scores: ROAP 0.9 (honest silver 0.765; the 1.0 entries
are leak exploits), insults 0.95 (Kaggle winner 0.8425). Round 0 was re-collected with the new thresholds;
memory had not been read by any improver yet.

## Change after round 1 (before its improve session)

`train_only_field` flagged 20/25 nodes for `request_text`, but they only used it as a name prefix
(`for t in ["request_text", "request_title"]: df[f"{t}_sentiment_..."]`, built from request_text_edit_aware).
Loop values used only inside f-strings/concatenation no longer count. Round 1 re-collected; old record in
`.state/superseded/`. Round 0 was unaffected (0 hits either way).

## Change after round 2 (before its improve session)

Round 2 (H2): 6/16 nodes had CV AUC 0.916-0.935 from SMOTE applied to the whole training set before
cross-validation (synthetic rows leak across folds; 0.70 -> 0.815 -> 0.935 along one lineage). The 0.897
"best trusted" node is inflated the same way but sits under 0.9: a fixed threshold cannot catch every case.
Evidence lines now also show resampling statements (resample/SMOTE/oversample), last 5 lines.
Round 2 re-collected.

## Deviation after round 2: improver fixed, H3 regenerated (not run)

The first H3 (old improver) only reworded "prefer trusted nodes" and raised num_drafts. Across three sessions
the improver (a) changed rule-mode-only keys every time (debug_prob, max_debug_depth, num_drafts), which do
nothing in agent mode, and (b) wrote notes in the loop's own vocabulary ("flagged", "trusted"), which AIDE
never sees, and never named the mechanism shown in the evidence code lines (in-sample stacking AUC, SMOTE
before CV). Running that H3 would have measured noise, so it was not submitted (kept in .state/superseded/).

Changes: the improver is shown only the keys its mode reads, and check/finish/loop reject changes to the
others; its prompt says what AIDE can and cannot see, and asks it to name the mechanism behind a verifier
result. H3 was regenerated from the same memory (rounds 0-2). Rounds 0-2 stay as they are; the report
treats rounds 0-2 (improver v1) and 3+ (improver v2) as separate segments.
Second regeneration: improver v2 on gpt-4o still wrote "avoid flagged nodes" and did not name SMOTE/in-sample
evaluation although those code lines were in its first message. H3 regenerated once more with gpt-5.4 as the
improver model (priced at a conservative $5/$40 per 1M tokens in the budget). AIDE itself stays on gpt-4o.

## Change after round 3 (before its improve session): new verifier

Round 3 (H3, first improver-v2/gpt-5.4 harness): every verifier read 0, yet official AUC fell to 0.572 (lowest
so far) with submitted CV AUC 0.779. Cause: SelectKBest-style feature selection and GridSearch fitted on all
training rows with labels, then cross_val_score on the same rows (0.658 -> 0.774 at step 6). H3's notes had told
AIDE not to do this; AIDE did it anyway. The 0.9 threshold cannot see a 0.78 that should be 0.65, so the vector
looked perfect while the score dropped (Goodhart on our own verifier set).
Added `preprocessing_outside_cv` (static ast check, see its docstring). On the 21 older ROAP runs it flags
2 of 3,073 scored nodes (0.07%), so it is not a common false positive. Rounds 0-3 re-collected with it; memory rebuilt.

## Decision after round 5: stop the ROAP loop, spend the rest on held-out + one replicate pair

Rounds 4 and 5 were clean on every verifier except search_health (submitted val 0.632/0.657 vs official
0.604/0.628: the first rounds where validation matched test). The rules allowed one more ROAP round
(spent $10.04 + $3 <= $14), but with the vector saturated another round mostly samples official-score noise.
Instead: (1) held-out as planned, insults with H0 and H5; (2) one more ROAP run each for H0 and H5
(replicates, evaluation only, not written to memory), so each harness has n = 2 on the train task.
Note for the held-out reading: H5's notes contain ROAP-specific content (field names, "mid-0.6 AUC").

## Held-out round: both insults runs invalid (task-env defect)

insults H0 (j1498164) and H5 (j1498165) both produced invalid submissions ("Submission should have an Comment
column"): the grader joins on the Comment text, and MLE-bench's description only says "see
sample_submissions_null.csv" (misspelled). H0 wrote `Insult`, H5 wrote `id,insult`. First insults runs on this
setup; the env was never smoke-tested. Official held-out comparison: no information (both invalid = 0).
Process verifiers did differ: H0 preprocessing_outside_cv -1, selection -1; H5 both 0 (n = 1).
Fix: task.json `task_notes` (fixed, not editable by the improver) states the format and is placed before the
harness notes. ROAP has no task notes, so its prompt variants are unchanged. Not re-run: the $20 cap allows
either this pair or the planned ROAP H5 replicate; the replicate was run.
