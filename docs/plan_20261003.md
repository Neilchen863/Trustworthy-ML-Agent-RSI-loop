# First experiment: ROAP loop + one held-out check (written before round 0 finished)

Budget: $20 total (`rsi budget`). $6 of it is kept for the held-out check, so ROAP rounds stop once
spent + $3 reserve would pass $14.

## Each round t on random_acts_of_pizza (train)

1. `collect` round t (delivery check must pass; a delivery failure stops the loop until fixed).
2. `improve` round t -> H{t+1} (gpt-4o, at most $0.5 per session).
3. Submit round t+1 unless a stop rule below holds.

## Stop rules for the ROAP loop (any one)

- Budget: spent + $3 > $14.
- Two consecutive `no_change` sessions (the improver sees nothing to fix).
- An improver session ends `error`/`unfinished`/`rejected` twice in a row.
- A run fails as infrastructure (no journal, killed job): resubmit once; a second failure stops.

## Held-out check (insults, test role)

After the loop stops: run insults once with H0 and once with H_final (the last harness), same budget.
Report both reward vectors and both official scores (read for the report only; never written to memory).
Skip if H_final == H0.

## How results are read

n = 1 run per harness. No round-to-round change is called an effect. What is reported: the trajectory of
the reward vector, what each harness edit was and which verifier it cited, and whether the verifier the
edit targeted moved in the next round. Execution failures count as outcomes (score 0 / reward -1), not
missing data.
