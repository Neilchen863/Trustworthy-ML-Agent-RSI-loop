## What the harness became

- H1/H2 (gpt-4o improver): "prefer plausible validation, avoid flagged nodes", "avoid train-only fields",
  plus rule-mode knobs that do nothing in agent mode. The notes used the loop's own labels, which AIDE never sees.
- H3-H5 (gpt-5.4 improver, v2 prompt): named the mechanisms from the evidence code lines: put every
  label-using step (selection, SMOTE, target encoding, tuning) inside a Pipeline evaluated by CV; never treat
  in-sample predictions as validation; pre-submission leakage checklist; only train/test-intersection fields;
  check the schema before coding; enable the submission profile. They also say "CV above ~0.90 is suspicious"
  (our verifier threshold) and "honest AUC is mid-0.6" (derived from official scores in memory; wrong for
  other tasks).

## Reading

1. **No evidence that the loop improved the official score.** H0 runs: 0.599, 0.646. H5 runs: 0.628, 0.644.
   n = 2 per harness; the H0 replicate alone matches H5.
2. **Leakage in the submitted node is episodic, not fixed by a harness.** Submitted node flagged: H0 1/2,
   H1-H3 3/3, H4-H5 0/3. The clean H0 replicate shows stock AIDE can also be clean, so the 0/3 for H4-H5 is
   compatible with chance (exact 95% interval for 0/3: [0, 0.71]).
3. **Validation became honest when the run was clean, not better.** Clean submitted nodes had val 0.63-0.67
   against official 0.60-0.65. Leaky ones had val 0.71-1.00 and did not score higher (0.57-0.65).
4. **The verifier set was the part that improved, and it needed to.** Three leakage mechanisms appeared in
   four runs (in-sample stacking score, SMOTE before CV, label-using selection before CV); none involved
   train-only fields. A fixed "implausible" threshold missed the 0.78 case, so in round 3 the vector read
   all-zero while the score was the lowest (Goodhart on our own verifiers). `preprocessing_outside_cv` was
   added; it flags 2 of 3,073 scored nodes in 21 older ROAP runs.
5. **The improver model mattered more than the improver prompt.** gpt-4o wrote notes in the loop's
   vocabulary and changed knobs that do nothing, even after the v2 prompt said what AIDE can see; gpt-5.4
   with the same prompt named the mechanisms and quoted the evidence lines.
6. **AIDE does not reliably follow notes.** H3 told it not to fit selection outside CV; it did, at step 6.
7. **Held-out: no information on score.** Both insults runs failed the submission format (the grader joins on
   Comment; MLE-bench's description only says "see sample_submissions_null.csv"). This was the first insults
   run on this setup. Process verifiers differed (H0 selection-before-CV, H5 clean), n = 1.

## Fixed during the experiment (all before the affected improve session; rounds re-collected)

- `implausible_val` 0.99 -> 0.9 (ROAP) / 0.95 (insults).
- Evidence shows the code lines computing the metric and any resampling.
- `train_only_field` no longer counts loop values used only as name prefixes.
- New verifier `preprocessing_outside_cv`.
- Improver v2: only active-mode config keys editable; prompt states what AIDE can see; gpt-5.4.
- Replicates (`--rep`, never written to memory); fixed per-task `task_notes` (insults submission format);
  byte-identical notes when a task has no task notes.
